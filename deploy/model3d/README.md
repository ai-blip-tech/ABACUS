# Room Design: автоматическая библиотека 3D-моделей

База: `origin/main` 746206689603c4a83228343d85e885c2ba008b3b (актуальная ревизия проверяется перед выпуском; фактический SHA — `git rev-parse HEAD`). Изменения из других рабочих папок не включаются.

## Что реализовано

* Отдельный координатор Node.js 22.13+ с SQLite WAL. Состояние очереди переживает перезапуск.
* Частная библиотека `/var/lib/room-design/model-library/objects/ab/<UUID>/reference.png` и `model.glb`; метаданные, права и задания — `library.sqlite`.
* Постоянный `assetId` не зависит от Pod, проекта, браузера или URL GPU. GET файла всегда проверяет владельца либо приобретённое право.
* Повтор того же референса, размеров и версии генератора внутри владельца использует готовый ID, не арендует GPU. Фотография/настройки хешируются после нормализации. Чужие приватные загрузки не становятся общим каталогом.
* Задание получает собственный короткоживущий токен. Аккаунтный RunPod API key хранится только в Амстердаме; HF key нужен только при сборке образа через BuildKit secret, не в браузере и не в слоях Docker.
* Worker самостоятельно забирает ввод по HTTPS, создаёт GLB и передаёт его в Амстердам. Браузерные скачивания и Jupyter не участвуют.
* GLB проверяется (заголовок, длина, JSON, число полигонов, отсутствие внешних ресурсов), записывается атомарно с fsync, затем подтверждается SHA-256. Повтор загрузки после потерянного ACK безопасен.
* После подтверждения результата координатор останавливает GPU; worker также вызывает остановку собственного Pod. Независимые watchdog-процессы в Амстердаме и GPU ограничивают максимальное время работы. Абсолютной гарантии остановки при недоступном API провайдера нет: ошибки записываются, новые аренды блокируются, остановка повторяется.
* Максимум GPU, максимальное время задания, суточный расчётный бюджет и верхняя ставка задаются на сервере. Бюджет резервируется до создания Pod с запасом на остановку. Фактическую тарификацию сверять с RunPod.
* Неопределённый ответ на создание Pod не вызывает повторный платный POST. Координатор ищет Pod по сохранённому уникальному имени. Неопределённый запуск, который не удалось подтвердить до дедлайна, оставляет защитную блокировку новых аренд до проверки оператором.

## Публичная вкладка и продажа

Новый экран не рисуется. Генерация пока разрешена только администратору; платежи пользователя не списываются. Перед открытием публичных платных запросов нужны тариф, резервирование/списание/возврат денег и серверный обработчик подтверждённой оплаты.

Для выдачи ранее созданной модели предусмотрен серверный `POST /internal/assets/<assetId>/grants` с `tenantId`, `userId`, `receiptId`. Его нельзя вызвать через публичный Next.js gateway. Выдача идемпотентна по квитанции, не создаёт нового GPU-задания. Модель должна быть предварительно опубликована владельцем-администратором через серверный `/publish` с `rightsConfirmed: true`. Личные фотографии и результаты не публикуются автоматически. Проверку платёжного провайдера выполняет будущий billing-обработчик, а не этот метод.

## Готовый образ GPU (один раз)

```sh
DOCKER_BUILDKIT=1 docker build --platform linux/amd64 \
  --secret id=hf_token,src=/secure/path/hf-read-token \
  -f deploy/model3d/Dockerfile -t PRIVATE_REGISTRY/roomdesign-trellis:release .
docker push PRIVATE_REGISTRY/roomdesign-trellis:release
docker run --rm --entrypoint cat PRIVATE_REGISTRY/roomdesign-trellis:release /opt/model3d/build.json
```

Образ содержит веса DINOv3: использовать **закрытый registry**. Его digest записывается в `MODEL3D_RUNPOD_IMAGE`, `engineRevision` из `build.json` — в `MODEL3D_ENGINE_REVISION`; worker проверяет ревизию внутри образа. RunPod registry credential задаётся существующим `MODEL3D_REGISTRY_AUTH_ID`. Исходники TRELLIS закреплены на 75fbf0183001ed9876c8dbb35de6b68552ee08bd. Используется проверенная в эксперименте связка Torch 2.8/CUDA 12.8, xFormers CUTLASS, DINOv3, BiRefNet.

Сборка Docker и холодный запуск образа должны быть отдельно проверены на Linux/amd64. Они не проверены только наличием успешного ручного теста TRELLIS. Большой образ с весами тоже может потребовать времени на первый pull; 94 секунды не являются SLA холодного запуска.

## Установка в Амстердаме

1. Проверить SSH, место, действующий main и production commit. Убедиться, что завершены все аренды с нашим namespace.
2. Загрузить проверенный release, выполнить `sudo bash deploy/model3d/install.sh`. Установщик делает резервную копию прежнего сервиса, конфигурации и библиотеки; не обновляет основной сайт.
3. Заполнить `/etc/roomdesign-model3d.env` с правами 0600. `RUNPOD_API_KEY` — действующий ключ владельца аккаунта с необходимыми правами управления Pod. Доступ к private registry настраивает владелец аккаунта.
4. Оставить `MODEL3D_GENERATION_ENABLED=false`, пока не проверены образ, callback и тестовый бюджет. Суточный бюджет по умолчанию 0. Новых расходов без явной настройки нет.
5. Добавить `MODEL3D_SERVICE_SECRET` (тот же, что в сервисе) и `MODEL3D_INTERNAL_URL` в **серверное** окружение Next.js. Установить только новые gateway/lib-файлы через штатный выпуск основного сайта с его бэкапом и проверкой; не заменять страницы других этапов.
6. Добавить Nginx worker location из примера; сначала `nginx -t`, затем reload. Внешние запросы к 4199 не открывать: сервис слушает только loopback. Обычные jobs/assets идут через сессию Next.js.
7. Проверить приватную загрузку, 401 без сессии, недоступность чужой модели, callback, файл из библиотеки. Затем ограниченный одинарный live-job, сверка SHA, остановка GPU и повторный cache hit без GPU. Только после этого считать сервис боевым.

Запуск:
```sh
systemctl restart roomdesign-model3d
systemctl status roomdesign-model3d roomdesign-model3d-watchdog.timer
journalctl -u roomdesign-model3d -n 100
```

Откат: при нулевом числе активных GPU отключить сервис, вернуть `/opt/roomdesign-model3d` и env из `/var/backups/roomdesign-model3d/<stamp>`. Не откатывать библиотеку поверх новых готовых моделей: сначала сохранить текущую копию; immutable GLB и новые права доступа не удалять. Откат gateway основного сайта — штатным production rollback.

## Контракт Pascal / будущей вкладки

* `POST /api/models3d/jobs`, JSON: `name`, `widthMm`, `depthMm`, `heightMm`, `resolution` (`512`/`1024`), `imageDataUrl` **либо** `catalogProductId`; заголовок `Idempotency-Key` UUID.
* `GET /api/models3d/jobs/<jobId>`: состояние, сообщения, `assetId`, `modelUrl`.
* `GET /api/models3d/assets`: доступные пользователю готовые модели.
* `GET /api/models3d/catalog`: только опубликованные модели для будущей витрины. Просмотр карточки не даёт право скачать файл.
* `GET /api/models3d/assets/<assetId>` и `/file`: метаданные и GLB с проверкой доступа.
* `lib/model3d-client.ts`: отправка и polling. При потере связи повторять тот же ключ либо проверять сохранённый jobId, не создавать новую заявку.
* В Pascal после готовности загрузить GLB, привести размеры к подтверждённым миллиметрам, сохранить `assetId` и локальный assetRef, сохранив координаты/поворот предмета. Браузерный blob URL не заменяет постоянный assetId.
* `pascal-adapter.ts.example` — готовый адаптер для существующего отдельного Pascal-приложения: `generateItemModel`, `resumeItemModel`, `installLibraryModel`. Скопировать вместе с `lib/model3d-client.ts` в Pascal package; его зависимости не добавляются в основной Next.js сайт.

Тесты без GPU:
```sh
node --test tests/model3d/*.test.mjs
```
