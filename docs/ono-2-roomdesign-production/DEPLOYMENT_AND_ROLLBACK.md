# Безопасный деплой и откат ОНО 2.0 — Room Design

## Миграции данных

ОНО создаёт три новые группы таблиц при первом обращении:

- `ono_chat_sessions`, `ono_chat_messages` — память диалогов;
- `ono_cost_ledger` — неизменяемый финансовый ledger с уникальным `request_id`;
- `ono_quality_events` — технические метрики качества.

Миграции добавочные: существующие таблицы проектов, пользователей, балансов, генераций и каталога не меняются. Для старой версии `ono_quality_events` предусмотрено безопасное добавление `request_kind` и `first_response_ms`. Автоматического удаления колонок или данных нет.

При откате кода новые таблицы следует оставить в SQLite. Это сохраняет аудит расходов и позволяет быстро вернуть ОНО 2.0. Физическое удаление таблиц является отдельной необратимой операцией и в аварийный откат не входит.

## Переменные окружения

Обязательные:

- `OPENAI_API_KEY` — только серверный secret;
- `OPENAI_TEXT_MODEL=gpt-6.1-sol`;
- `NEXT_PUBLIC_ONO_V2_ENABLED=true` — включает UI на этапе сборки;
- `ONO_V2_ENABLED=true` — runtime-допуск API.

Опциональные:

- `ONO_ENABLE_WEB_SEARCH=false` для первого production-релиза;
- `ONO_KNOWLEDGE_VERSION` — фиксированная версия базы знаний;
- `ROOM_DESIGN_DATA_DIR` или `DATA_DIR` — действующий постоянный каталог SQLite и object storage.

`ONO_NORR_*`, SDK-конфигурация NORR и Telegram в этот релиз не входят.

## Резервная копия

1. Перевести запись приложения в короткое сервисное окно либо остановить процесс.
2. На production VPS отдельно скопировать `/var/lib/room-design` (или фактический `ROOM_DESIGN_DATA_DIR`), включая SQLite/WAL/SHM и `storage`. Текущий GitHub Actions workflow такой data-backup автоматически не создаёт.
3. Выполнить SQLite integrity check, проверить ненулевой размер копии и сохранить checksum.
4. Зафиксировать production commit, environment snapshot без значений секретов и время копии.
5. Локальная audit-копия не заменяет remote backup. Только после успешной VPS-копии запускать release candidate.

## Порядок публикации

1. Создать release candidate от зафиксированного `origin/main` по allowlist из `RELEASE_MANIFEST.md`.
2. Повторить build, 208 Node-тестов, release-scope ESLint и 6 browser-сценариев ОНО.
3. Собрать приложение с `NEXT_PUBLIC_ONO_V2_ENABLED=true`, но запустить первый раз с `ONO_V2_ENABLED=false`.
4. Проверить `/api/health` и `/api/it/config`; при выключенном флаге UI не должен появляться, а `/api/it` должен отвечать 503 без новой строки расходов.
5. Включить `ONO_V2_ENABLED=true` и перезапустить один production-процесс.
6. Выполнить post-deploy smoke ниже.

## Post-deploy smoke

- На главной ОНО отсутствует; на `/templates`, конкретном шаблоне, кабинете и существующем проекте присутствует ровно один виджет.
- Текстовый запрос отдаётся потоком и создаёт ровно одну запись `ono_cost_ledger`.
- Повтор того же `request_id` не вызывает модель повторно.
- История восстанавливается после перезагрузки и не видна другому пользователю/tenant.
- PNG/JPEG/WebP анализируется без запуска генерации изображения.
- Навигационная подсказка только подсвечивает/фокусирует элемент и ничего не нажимает.
- Проекты, шаблоны, каталог, авторизация и баланс пользователя работают как до релиза.
- В админском отчёте NET/GROSS появляется один раз и использует неизменённый коэффициент.
- Повторить основные шаги на desktop и mobile.

## Быстрый откат

1. Установить `ONO_V2_ENABLED=false` и перезапустить приложение — это немедленно блокирует GET/POST/DELETE ОНО до вызова модели и создания расходов.
2. Если проблема только в ОНО, оставить новую сборку с выключенным флагом и исследовать логи.
3. Если затронуто приложение, вернуть предыдущий production commit/артефакт и перезапустить процесс.
4. Новые таблицы ОНО не удалять. Восстанавливать всю SQLite-копию только при подтверждённом повреждении существующих данных, потому что полный restore откатит и пользовательские действия после момента backup.
5. После отката проверить авторизацию, список проектов, балансы, генерацию изображений и `/api/health`.

## Условия немедленной остановки

- второй виджет или второй запрос к модели на один `request_id`;
- любое изменение пользовательского баланса от текстового диалога ОНО;
- смешение истории пользователей или tenants;
- потеря проектов/генераций или ошибка авторизации;
- расхождение NET/GROSS, раскрытие API-ключа или массовые 5xx.
